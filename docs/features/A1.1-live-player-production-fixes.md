## P0 Root Causes & Fixes

### 1. Student Submit Not Working

**Root cause (multi-factor):**

| Layer | Issue |
|-------|-------|
| WebSocket | Play connections did not use `mode=play`, so hosts testing the play URL had **no `participantId`** — answers were silently dropped |
| WebSocket | `answer` handler returned without error when `participantId` missing |
| Frontend | `submitAnswer` sent blindly; UI set `answered=true` before server confirmed |
| Frontend | No error surfaced to student on failure |

**Fix:**

- `getLiveSessionWsUrl(sessionId, mode)` — student page uses `mode: "play"`
- Server joins participant when `!isHost || mode === "play"`
- Server sends `error` WS message if answer submitted without participant
- Student UI waits for `answer_result` before marking answered
- Toast on submit failure; reconnect banner when disconnected
- After answer: broadcast `leaderboard` + full `session_state` for score sync

**Pipeline verified:**

```
LiveQuestionDisplay → submitAnswer() → WS { type: "answer" }
  → submitLiveAnswer() → gradeAnswer() → DB persist
  → answer_result (student) + leaderboard + session_state (all clients)
```

### 2. Blank Questions & Options

**Root cause:**

- `createEmptyQuiz()` seeds questions with **empty `text` and empty option `text`**
- No validation blocked hosting a draft quiz live
- Live player rendered empty strings literally

**Fix:**

- `liveQuizValidation.ts` — `assertQuizReadyForLive()` called in `startSession()`
- Blocks start if any question lacks text, options, or correct answer
- `questionDisplayText()` / `optionDisplayText()` fallbacks for edge cases (Option A/B, True/False)
- `MarkdownContent` renders question stem and option text

**Instructor action required:** Fill in question text and options in Quiz Builder before hosting. Empty quizzes now receive a clear error on Start.

---

### 3. Timer Starts at 0 Seconds

**Root cause:**

- Client timer used server `questionStartedAt` (set when **host** starts session)
- Students joining late or reconnecting inherited elapsed time → `timeLeft = 0`
- `questionTimerSeconds` could be `0` or missing from malformed settings JSON

**Fix:**

- `parseSettings()` enforces minimum 5s timer (default 30s)
- Student timer uses **local anchor** when question loads (`question.id` change)
- Each student gets full configured duration when they see the question
- Server still uses `questionStartedAt` for speed-bonus scoring (fair competitive scoring)

---

### 4. Leaderboard Updates

**Root cause:**

- After answer, only `leaderboard` message was broadcast — `sessionState.participants` in hook could be stale
- Header score/rank on student page reads from `leaderboard` state

**Fix:**

- WS `leaderboard` handler updates both `leaderboard` and `sessionState.participants`
- After answer, server also broadcasts `session_state` with fresh rankings
- `previousRanks` updated for movement indicators

## P1 — Instructor Analytics

**Root cause:** Analytics polled every 2s only; `answer_received` WS event was ignored.

**Fix:**

- `useLiveSessionSocket` accepts `onAnswerReceived` callback
- Host page refetches analytics immediately on each answer + on leaderboard change
- Participant status (answered/thinking) updates via analytics API

## Before / After

### Before
- Submit appeared to do nothing (silent WS drop or optimistic UI)
- Blank question stems and option rows for untitled/default quizzes
- Timer showed 0s for late-joining students
- Leaderboard header score stuck at 0
- Host analytics lagged 2+ seconds

### After
- Submit confirms via `answer_result`; errors shown via toast
- Validation blocks empty quizzes; markdown renders content
- Timer starts at full duration per question view
- Scores sync via leaderboard + session_state
- Analytics refresh on every answer
