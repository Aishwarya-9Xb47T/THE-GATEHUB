# A1.4 — Live Player Selection Fix

> **Status:** Fixed — awaiting manual QA sign-off  
> **Severity:** P0 — blocked entire live assessment flow  
> **Date:** July 6, 2026

---

## Symptom

Student opens live quiz question (MCQ / True-False). Options and radio circles render. Clicking an option does **nothing** — no highlight, no selection. Submit stays disabled with label **"Select an answer"**.

Screenshot: student on Q1/8, True/False options visible, submit disabled.

---

## Root cause

**Circular disabled-state dependency** introduced in A1.2 player flow refactor.

### Broken chain

```
LiveSessionPlayerPage
  disabled={!canSubmitNow}          ← single prop for entire question card
    ↓
LiveQuestionDisplay
  <button disabled={disabled}>      ← option buttons use same flag
    ↓
canSubmitNow = canSubmit(phase) && hasSelection && !submitInFlight
```

When `hasSelection === false` (initial state):

1. `canSubmitNow` → **false**
2. `disabled={!canSubmitNow}` → **true**
3. Option `<button disabled>` → **clicks ignored**
4. `onSelectionChange` never fires → `hasSelection` stays **false**
5. Deadlock — student cannot select

This was **not** a radio component bug, CSS `pointer-events`, z-index, or WebSocket issue. The HTML `disabled` attribute on option buttons prevented all interaction before first selection.

### Where state stopped updating

| Layer | Expected | Actual |
|-------|----------|--------|
| Mouse click | Reach handler | Blocked by `disabled` on `<button>` |
| `updateSelection` | Update local `selected` | Never called |
| `onSelectionChange` | Set `hasSelection` in flow hook | Never called |
| `canSubmitNow` | false until selection | Stuck false forever |
| Submit button | Enable after selection | Permanently disabled |

---

## Fix

**Separate option interactivity from submit eligibility.**

| Prop | Controls | Depends on `hasSelection`? |
|------|----------|:--------------------------:|
| `optionsDisabled` | Option button clicks | **No** |
| `submitDisabled` | Submit button | **Yes** (via `canSubmitNow`) |

### New data flow

```
phase === QUESTION_ACTIVE
  ↓
canSelectOptions = canSelectOption(phase) && !submitInFlight   // true
canSubmitNow = canSubmit(phase) && hasSelection && !submitInFlight  // false until click
  ↓
optionsDisabled={!canSelectOptions}   // false → options clickable
submitDisabled={!canSubmitNow}        // true until selection
  ↓
Click option → updateSelection → onSelectionChange → hasSelection=true
  ↓
canSubmitNow=true → Submit enabled
```

## Prevention

1. Never bind **option** `disabled` to **submit** preconditions (`hasSelection`).
2. Code review rule: `canSubmitNow` is for submit button only.
3. Unit test enforces `canSelectOptions` true when `hasSelection` false.
